# celld smoke test

A first check of whether cell-docs-lab runs on [celld](https://github.com/denoland/celld),
Deno's open-source, self-hosted runtime for Cloudflare Workers and Durable
Objects. This is the start of Phase 5 (compatibility testing), not the full
compatibility run.

**Result:** the app runs on celld **without code changes**. It needs a
celld-specific config file and one generated file removed from the build
output. 22 of 23 checks passed; the remaining one is a harmless difference in
how unknown page paths are answered.

## Setup

| | |
|---|---|
| Date | 2026-10-26 |
| celld | v0.6.3, release asset `celld-aarch64-apple-darwin.gz` (no checksum is published; SHA-256 of the unpacked binary: `76a95349d7eab84faf842fcbf41be5112e7cd7c9b721ed99ddfea7b2d057e121`) |
| Machine | macOS 15.5, Apple Silicon |
| Node.js | 23.11 |
| Project | commit `8993d90` (end of Phase 4) |
| Mode | `celld dev`: one node, local storage, no bucket |

The test ran on a throwaway copy of the project, so nothing in this
repository was changed to make it run. celld needs `esbuild` on `PATH`; the
project's `node_modules/.bin` provides it.

## Getting it to start

| Attempt | Result |
|---|---|
| Unchanged `wrangler.jsonc` | Refused: ``celld deploy` does not support these config keys: observability`` |
| The deploy config generated by the Vite build (`dist/cell_docs_lab/wrangler.json`) | Refused: about 30 keys that Wrangler fills in by default (`configPath`, `dev`, `exports`, `observability`, …) |
| A minimal `celld.jsonc` (below) | Refused: `dist/client/.assetsignore is not supported by celld deploy` |
| The same, with `dist/client/.assetsignore` deleted | **Starts in about 1 second**; both classes are recognised as `Durable Object (SQLite)` |

`celld.jsonc` is `wrangler.jsonc` with two changes:

- `observability` removed. celld rejects any top-level key it does not know.
- `assets.directory` set to `./dist/client`. Under Vite, the Cloudflare plugin
  supplies the asset folder; celld needs it in the config, and the client
  must be built first (`npm run build`).

`dist/client/.assetsignore` is written by the Cloudflare Vite plugin during
the build (it lists `wrangler.json` and `.dev.vars`). celld does not support
that file.

| Data after a crash (`SIGKILL`) and restart, REST and Yjs | Pass |

These pass on celld even though its documentation does not list them by name:
`ctx.storage.sql`, nested `transactionSync`, `getWebSockets`, WebSocket
attachments (`serializeAttachment`) and the project's own save-check message.

### Single-page-app fallback

| Request to `/some/client/route` | Local workerd (Vite) | celld |
|---|---|---|
| Browser navigation (`Sec-Fetch-Mode: navigate`) | 200, the app | 200, the app |
| Plain request (for example `curl`) | 200, the app | 404 from the Worker (JSON) |

celld serves the app for browser navigations and sends other unknown paths
to the Worker, which answers with its JSON 404. Users always navigate, so
they are not affected. It is not yet verified which of the two behaviours
Cloudflare's own platform shows for this config.

## Not covered

- The project's 3 integration and 14 browser tests. They start Vite
  themselves; running them on celld needs a runtime switch in
  `test/integration/dev-server.ts`.
- A multi-node fleet with bucket replication, and cells moving between nodes
  (celld then closes WebSockets with code 1012).
- A cell hibernating while sockets stay open, load, and timing.
- The 78 unit tests: they run inside workerd's test pool by design.

## Suggested next steps

1. A runtime switch for the integration and browser tests, so all of them run
   on both runtimes.
2. Keep `celld.jsonc` in the repository and drop `.assetsignore` in a small
   build step, so celld runs from a normal checkout.
3. Then a multi-node run with an S3-compatible bucket.

## Reproducing

```sh
# celld v0.6.3 for Apple Silicon, into a folder of your choice
curl -fsSL -o celld.gz https://github.com/denoland/celld/releases/download/v0.6.3/celld-aarch64-apple-darwin.gz
gunzip celld.gz && chmod +x celld

# in a copy of the project, with celld.jsonc created as described above
npm run build
rm dist/client/.assetsignore
PATH="$PWD/node_modules/.bin:$PATH" /path/to/celld dev celld.jsonc --port 9879 --no-watch
curl localhost:9879/api/health
```

State is kept in `.celld/dev` next to the config; `--clean` starts empty.
